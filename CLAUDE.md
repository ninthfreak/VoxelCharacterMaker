# Project: character system for a JRPG-style game (Godot 4). Low-poly

**The characters are low-poly (owner's decision, 2026-11). That is the project, not an experiment or a study:** build
it as product work, say so in plain terms, and commit as you go. Read `SPEC.md` section 0 first; `lowpoly/README.md`
says what exists. The earlier voxel system was removed (2026-11, phase 5 of the move; the last commit with it is
`fa40fa0`); SPEC sections 1 to 13 keep its decisions, and mark what was voxel only.

Read `SPEC.md` before any work; it holds every decision made so far. If something there seems wrong, raise it rather
than silently changing course.

## Working with the owner
- They assess risk and tradeoffs themselves. Give accurate feasibility reads, keep uncertainty visible, rate
  difficulty and confidence explicitly, and state recommendations as recommendations, never as decisions.
- Ask when a choice is genuinely theirs (style, look, scope). Make the call on routine engineering.
- When an answer is needed, ask it as one clearly marked question at the very end of the message. A question inside a
  report gets missed. One question at a time.
- They are red/green colour blind, dyslexic and have ADHD: no red-vs-green-only signals in UI or debug views, short
  clear labels, readable text, summaries before detail.
- Show visual results (screenshots/renders) for anything that changes how characters look.
- Anything the owner edits must be edited by hand: click, drag, handles in the view. Number boxes are for fine work
  and exact places only, never the main way in (owner, on the first Items tab: "I'm not a machine like you").

## Conventions
- Engine: current stable Godot 4.x, GDScript. The character assembly code (body + head + face + worn items -> a
  dressed figure: `core/lowpoly/lowpoly_assembler.gd`) exists exactly once and is shared by the game and the editor.
- Asset files use the axes in SPEC.md §2 (x across, y depth with front at -y, z up, 24 units per metre); convert to
  Godot space only through `FigureAxes` (`core/figure_axes.gd`).
- The rules are made in Python first (`lowpoly/`) and built the same way in GDScript (`core/lowpoly/`), in full
  precision (`Vec64`); `tests/test_lowpoly.gd` holds Godot to the Python's corners through
  `tests/lowpoly_expected.json`. A change to a rule is made in both, and the expected file regenerated.
- Body, head and region files under `assets/lowpoly/` (the game reads them; OBJ copies in `lowpoly/bodies/` and
  `lowpoly/heads/`) are generated by `lowpoly/body.py` from the clay bodies in `lowpoly/clay.py` and by
  `lowpoly/heads.py`; `tests/lowpoly_expected.json` by `lowpoly/expected.py`. Regenerate rather than hand-edit.
  `python3 lowpoly/check.py` checks them.
- `lowpoly/` reads the game's wardrobe, poses, settings, eyes and colours from Godot each time (`lowpoly/game.py`);
  do not copy those tables into Python.
- Before showing any generated mesh, run its geometry check and look at every part of it at full size.
- Tests run headless (`tests/run.sh`, or `godot --headless --path . --script res://tests/run_tests.gd`); every
  check that can be automated should be.
